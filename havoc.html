About the project

Havoc is an open, API-first platform for storing, versioning and serving structured data. Instead of fixed data models, entity types are defined with JSON Schema, and Havoc manages content with a complete version history, a review workflow and role-based permissions. Everything is available through a versioned REST API.

Havoc separates data from applications: websites, apps and internal tools can all share one reliable data layer without being tied to a particular front end.

Features

What Havoc does

{ }

Schema-defined entities

Define your own entity types with JSON Schema instead of fixed models. Every entry is validated against its schema.

v2

Immutable history

Every change creates a new version. Earlier versions are never overwritten, so the full history of each entry stays traceable.

✓

Review workflow

Changes can be reviewed before they are published, keeping the shared data reliable.

RBAC

Role-based access

JWT authentication for users, API keys for service clients, and passwords hashed with bcrypt.

/api

Versioned REST API

All data is served as JSON through a versioned API, with interactive OpenAPI documentation at /docs.

⌕

Full-text search

Flexible attributes are stored as PostgreSQL JSONB, with built-in full-text search across content.

From course to project

How CS50 led here

The whole backend is written in Python, building on the language introduced in Week 6.

Relational design with tables, constraints and indexes, scaled up from SQLite to PostgreSQL, with SQLAlchemy and Alembic managing the schema.

Routes, requests and responses carry over directly from Flask to FastAPI. The difference is that Havoc returns JSON for other programs instead of HTML pages.

Guarding against SQL injection (Week 7) and Finance's login system with hashed passwords and sessions (Week 9), extended to JWT, API keys and role-based access.
